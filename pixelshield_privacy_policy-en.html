🛡️ PixelShield Privacy Policy

A safe and reliable offline privacy protection and copyright protection tool | Last updated: July 2026

[No Network Access · No Data Upload]
⚡ PixelShield is designed not to request network access.
Your images, verification records, and verification information generated by the app are all processed and stored locally on your device. PixelShield will not upload your images, verification data, or device-bound information to any server, and the developers will not keep any copies of your user data.
1. What data do we collect and process?

1) Explanation of personal information

We don’t collect any personally identifiable information. PixelShield doesn’t offer user registration or login features and doesn’t ask for your name, phone number, email, or any other identity details.

This app doesn’t include online ads, analytics, user tracking, or push SDKs, and it doesn’t have any data collection, user behavior analysis, or remote crash reporting features.

2) Image Processing and Metadata Description

PixelShield's main features are photo privacy protection and copyright protection, performed entirely on your device.

When you choose a photo to process, the app might read some information from the file, like:

  • Photo file details;
  • EXIF metadata (such as camera information, capture time, GPS coordinates, etc.).

This information is only used for:

  • Removing privacy-related metadata from your photos;
  • Creating copyright protection information;
  • Completing the photo tasks you initiate.

All photo processing happens locally on your device. PixelShield does not upload your photos, EXIF info, or processed files to any server.

3) Instructions for Handling Device Binding Information

To enhance the integrity verification capability of evidence exports, when you actively use the “Verification Package Export” feature and generate a notarized report containing Device Binding information, PixelShield may read limited device information locally.

This information may include:

  • Device identification information provided by the system;
  • Device brand and model information;
  • Some hardware identification information.

The above information is only used for:

  1. Generating an irreversible device-binding verification key;
  2. Writing into the Verification Report you actively export;
  3. Enhancing the integrity verification of the notarized file.

Device information processing workflow:

Device information -> Local hash calculation -> Generate device binding key -> Write into Verification Report

PixelShield won't upload the above device info, won't create a user device database, and won’t use it for user tracking, ad analysis, or any other commercial purposes.

2. Data Storage and Management

1) Local Storage

All verification records, verification history, and data needed for app operation are stored in your device's local private storage.

PixelShield uses a local database to save relevant records and does not rely on any cloud database or online service.

Processed images and verification files that users actively export are stored in locations on the device authorized by the user, for example: Download/PixelShield_Export.

2) User-exported files

When you actively export images, text reports, or verification packages, you manage the files yourself. PixelShield won’t access the files you later send to other apps or third parties using the system's sharing feature.

3) Data Transmission

The current version of PixelShield does not request network access permissions. All image processing, evidence generation, and device binding calculations are done locally, with no cloud transmission or cross-border data transfer.

4) Data Deletion

Users can delete local data in the following ways:

  1. Execute 'Reset Verification Records' on the app settings page;
  2. Clear the app's local data;
  3. Uninstall the app.

After uninstalling the app, the Android system will delete the relevant data in the app's private storage space according to the system mechanism.

3. Permission Details

PixelShield follows the 'least privilege' principle, only requesting the necessary system permissions when the user actively performs the related actions.

1) Image Access Permission

Used for:

  • Allowing users to select the photos they want to process;
  • Saving the processed image files.

PixelShield doesn’t scan, collect, or upload all the pictures on users' devices.

2) Storage access permission (if required by the system)

Used for:

  • Exporting Verification Reports;
  • Saving user-generated images or verification files.

The above permissions are only used for local file handling and do not involve network transmission.

4. Protection of minors

This app does not collect personal information and does not offer special features for minors. If minors use this app, please do so under the guidance of a parent or guardian.
